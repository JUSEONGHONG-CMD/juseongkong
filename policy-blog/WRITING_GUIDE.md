# 블로그 조회수 규칙 (원고 자동 생성용)

네이버 블로그 운영 기록과 검색 최적화 조사에서 추린 규칙이다. 근거 수준을 붙였다.

| 표시 | 뜻 |
|---|---|
| **[실측]** | 운영하며 통계·발행 결과로 직접 확인함 |
| **[공식]** | 네이버 발표 |
| **[보도]** | 기사 속 네이버 관계자 발언 |
| **[업계]** | 업체·블로거 주장(네이버 확인 없음). 해서 손해 없는 것만 채택 |

"적용"은 이 프로그램(`policy-blog`)이 코드 또는 지침으로 이미 지키는 것, "사람"은 발행하는 사람이 하는 것이다.

## 전제
- 네이버 블로그는 글쓰기 API가 없고(2020 종료), 매크로 자동 발행은 어뷰징 제재 대상이다 **[보도]**. → 원고를 메일로 보내고 **사람이 붙여넣어 예약 발행**한다. (적용)
- 유입은 거의 전부 검색이고, 모바일이 90% 이상이다 **[실측]**. 모바일 네이버 앱 화면을 기준으로 판단한다.
- 검색어는 **"고유명사 + 궁금한 속성"** 이다(예: `옥포 힐스테이트 평수`) **[실측]**. 우리 글은 **정책 이름 + 대상·금액·신청 방법·마감일**이 해당한다.

## 1. 제목 (적용: 검사)
1. **정책 이름(고유명사)을 맨 앞에**, 그다음 검색 속성(자격·지원금·마감일·신청 방법), 날짜는 맨 뒤 괄호. 날짜로 시작하는 제목은 검색에 안 걸렸다 **[실측]**. (`title` 이 `search_name` 으로 시작해야 발행됨)
2. 글마다 제목이 달라야 한다 **[업계]**. 같은 메일 안 중복 제목은 거부된다.
3. 과장 표현 금지(“무조건”, “역대급”, “놓치면 후회” 등) **[업계]**. `blog_config.json` 의 `banned_phrases` 가 걸린다.
4. 같은 단어 겹침(`오피스텔 오피스텔`)은 맞춤법 점검(빨간 칸)에 걸린다.
5. 긴 정책 이름은 머리말·꼬리말을 떼어 짧은 `search_name` 으로 쓴다.

## 2. 글 앞부분 (적용: 검사)
1. `one_liner`(첫 문장)와 `intro` 가 모두 **정책 이름으로 시작**해야 한다. 그날 글마다 달라지는 내용(대상·금액·마감)을 앞에, 인물 소개는 아래에 둔다 **[업계]**.
2. 여는 문장을 글마다 다르게 쓴다. 숫자는 공식 자료에서 가져온다 **[보도: 출처가 분명한 글 우대]**.

## 3. 본문 구조 (적용: 렌더러가 만든다)
- **한 줄 요약 문장**에 검색 속성(대상·금액·마감)을 모두 넣는다 **[실측: 사람들이 "평수", "분양가"처럼 속성 단어로 검색]**.
- **표는 요약표 1개(짧은 칸 4개)만**. 네이버 스마트에디터에 붙이면 칸이 많거나 긴 표는 너비가 깨진다 **[실측]**. 요건은 `▪ 항목` + 문단으로, 표에는 `width` 속성을 쓴다. 테두리 `div` 상자는 본문에 쓰지 않는다(메일 위 노란 안내 상자만 예외, 붙여넣을 본문이 아님).
- 다루지 못한 관련 정책은 `related` 에 **이름 + 속성 한 줄**로 남긴다(긴 꼬리 검색 유입) **[실측]**.
- 끝에 안내 문구(가상 인물·참고용·공식 문서 확인)와 `#해시태그` 한 줄을 둔다. 안내 문구는 지우지 않는다.

## 4. 이미지 (적용: 썸네일 생성 + 공개 주소 + 첨부)
- **메일 첨부(cid)·data URI 이미지는 본문에 쓰지 않는다**: 모바일·방문자에게 깨진다 **[실측]**.
- **로그인 없이 열리는 공개 주소**에 올리고 본문이 그 주소를 가리키게 한다 **[실측]**. 저장소 `public/<날짜>/<정책 id>/01_thumb.png` → `raw.githubusercontent.com/…`. 주소에 한글을 쓰지 않는다. **메일을 보내기 전에 이미지를 먼저 push** 한다. (저장소를 비공개로 바꾸거나 `public/` 을 지우면 발행한 글의 이미지가 모두 깨진다.)
- 같은 PNG 를 번호 붙인 첨부로도 보낸다. 대표 이미지(썸네일)만큼은 **사람이 사진 버튼으로 직접 올리면 가장 확실하다** **[실측]**(사람).

## 5. 썸네일 (적용: `make_thumb.py`)
1080×1080 PNG, 좌우 여백 8% **[업계]**. 큰 글씨 = **정책 이름 + 행동 문장**, 아래 띠 = **지원 내용 + 마감 D-n**, 위 띠 = **누구를 위한 글인지**(대표 인물 종류). 썸네일의 대상 = 제목·첫 문장의 대상. 글자가 넘치면 크기를 줄이고, 그래도 길면 띄어쓰기 단위로 자른다. 한글 글꼴이 없으면 만들지 않는다. 실존 건물 사진·로고·얼굴은 쓰지 않는다. 판정이 불확실한 글은 `thumb_action` 을 “확인해 보세요” 계열로 쓴다.

## 6. 태그 (적용: 검사)
고정 태그 6개(`blog_config.json`) + 이번 글의 정책 이름·주제·월 태그(최대 합계 20개) **[업계]**. 글과 관계없는 인기 키워드는 넣지 않는다(오히려 흐려짐) **[실측]**. 메일에는 쉼표 목록(태그 입력란용), 본문 끝에는 `#해시태그` 줄이 들어간다.

## 7. 발행 방식
- **하루 최대 3편, 예약 발행으로 시각을 나눈다**(메일에 12:30·16:30·19:30 안내). 몰아 올리면 도배로 보인다 **[보도]**. (적용: 메일당 3편까지, 예약 시각 안내)
- **받은 날 예약까지 끝낸다**(지난 정보가 섞이지 않게) **[실측]**(사람). 정해진 요일을 거르지 않는다 **[업계]**(사람).
- 새 소재가 없으면 만들지 않는다. 같은 내용을 반복하지 않는다. (적용: 이력 비교)

## 8. 블로그 자체 (사람)
- 주제를 바꾼 블로그는 검색 노출이 쌓이는 데 1~3개월 걸린다 **[업계]**. 조급해하지 않는다.
- 카테고리 이름은 `blog_config.json` 의 `category_map` 과 **글자 하나까지 같게** 맞춘다 **[실측]**. 붙여넣은 뒤 제목·카테고리·본문이 같은 글인지 확인한다 **[실측]**.

## 9. 정확성 장치 (적용)
- 이상 마감 제외: **오늘 마감이거나 지난 정책은 거부**(읽는 사람이 쓸 시간이 없다) **[실측]**.
- 맞춤법·표기 점검: 흔한 오기(됬·몇일·할께·되요), 같은 단어 반복, 문장부호 앞 공백, 빈 괄호, 고유명사 뒤 조사 → **메일 위 빨간 칸**. 사람은 붙여넣은 뒤 에디터 맞춤법 검사를 한 번 더 돌린다.
- 판정 표시: 해당될 가능성이 큰 사례는 ✅, 조건 확인이 필요한 사례는 ❔ 로 구분한다.
- (이 프로그램에는 단지 주소·시세 비교가 없어 위치 검증·이상치 삭제는 해당 없음)

## 10. 메일 형식 (적용)
정책마다 노란 상자: 카테고리, 제목, 태그(쉼표 목록), 예약 발행 시각, 사진 안내, 검증 메모(문제 있으면 빨간 칸), **발행 전 점검표 ☐ 8개**. 그 아래 빨간 선부터 끝까지가 붙여넣을 본문. 형식을 바꿀 때는 **시험 발송**(`TEST_MODE=1`: 제목에 [시험], 이력 미기록)으로 실제 붙여넣기를 확인한다.

## 11. 측정하고 고치기 (사람 → 지침)
주 1회 블로그 통계의 **유입경로 → 검색어**를 본다. 들어온 검색어에서 "고유명사 + 속성" 의 속성 단어(자격, 신청방법, 지원금, 마감 …)를 모아 알려 주면, `search_name`·`one_liner`·`summary_lines`·`thumb_action`·`hashtags` 규칙에 반영한다. 유입이 0인 글은 제목에 정책 이름이 앞에 있는지부터 본다.

## 12. 하지 말 것
매크로 자동 발행 / 같은 원고 재게시·다른 블로그 복붙 **[업계]** / 몇 편을 같은 시각에 즉시 발행 **[보도]** / 무관한 인기 키워드 끼워 넣기 **[업계]** / 메일 첨부·data URI 이미지를 본문에 사용 **[실측]** / 불확실한 판정을 ✅ 로 표기 / 안내 문구 삭제.
