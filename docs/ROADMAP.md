# Benefit Radar 확장 로드맵

지금은 한 가구(결혼 준비 커플)가 쓰는 개인용이지만, 안정화 후 다른 사용자도 쓰는 앱으로 수익화하는 것을 전제로 설계했다.

## 지금 구조에서 이미 준비된 것
- **엔진과 사용자 분리**: 코드·지침에 특정인 정보가 없고, 가구 프로필을 입력으로 받는다. 구성원 1~N명(1인 청년, 커플, 신혼, 자녀 가구)을 지원한다.
- **버전 있는 스키마**: `profile.schema.json`으로 앱 온보딩 폼을, `report.schema.json`으로 앱 결과 화면·푸시를 그대로 만들 수 있다.
- **채널 어댑터**: `scripts/channels/`에 모듈을 추가하면 앱 푸시, 카카오 알림톡 등을 붙일 수 있다.
- **제도와 판정 분리**: 제도 정보(id, 요건, 서류, 링크)는 사용자와 무관하므로 공유 DB로 옮길 수 있다.
- **사용자별 키**: `seal.sh`/`unseal.sh`가 키 환경변수 이름을 인자로 받는다.

## 단계
1. **개인용 (현재)** — 1가구, Claude Routine + GitHub Actions 메일. 판정 정확도와 메일 품질을 다듬는다.
2. **소수 베타** — 가구별 Routine/키 분리, 피드백(“도움 됐어요/틀렸어요”) 수집해 판정 규칙 개선. 저장소는 private 전환.
3. **공유 제도 DB** — 제도 수집(주 1회 전체 크롤링·요건 구조화)과 가구별 판정을 분리해 비용 절감. 요건을 기계 판정 가능한 규칙으로 저장.
4. **앱(웹/모바일)** — 온보딩 폼(스키마 기반), 결과 피드, 마감 알림 푸시, 서류 체크리스트, 신청 완료 기록.
5. **수익화 후보** — 월 구독(알림·자동 판정), 프리미엄(부부 공동 계정, 서류 준비 대행 가이드, 대출·청약 시뮬레이터), 제휴(정책금융 취급 금융기관).

## 앱화 전 개인정보보호 체크리스트 (개인정보 보호법)
- [ ] 수집·이용 동의(필수/선택 분리), 목적·보유기간 고지, 개인정보처리방침 게시
- [ ] 최소 수집: 판정에 필요한 항목만, 가능한 한 구간값(소득 구간 등)으로
- [ ] 소득·자산 등은 암호화 저장, 키 관리(KMS), 접근 권한·접근 기록
- [ ] 외부 AI·검색에 개인 식별정보 전달 금지(현재 규칙 유지), 처리 위탁 시 고지
- [ ] 탈퇴 시 즉시 파기, 보유기간 경과 데이터 자동 파기
- [ ] 주민등록번호 등 고유식별정보는 수집하지 않음
- [ ] 판정 결과는 "참고용, 최종 자격은 기관 확인" 고지(책임 한계)
